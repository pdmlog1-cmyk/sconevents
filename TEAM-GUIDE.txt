--------------------------------------------------------------------------
  4.  WHERE TO EDIT WHAT
--------------------------------------------------------------------------

Each conference has its own folder under  data\<slug>\
For example:   data\cardiology\

That folder contains 10 JSON files:

  conference.json    Conference name, short name, dates, city, venue, email
  marketing.json     Home page "Important Dates" box, headlines, CTA text
  registration.json  Pricing, Early Bird / Late phases, closing dates
  tracks.json        35 session tracks (only the first 6 show on the page)
  speakers.json      Speakers list
  committee.json     Organizing committee
  gallery.json       Photos
  common.json        FAQ questions & answers, footer text
  navigation.json    Menu links
  seo.json           Title & description shown in Google

To change design / layout (CAREFUL -- this affects all 10 pages):

  app\[conference]\LandingClient.tsx    Full page UI
  lib\conferences.ts                    Theme colors, gtag ID, main site URL
  lib\logoSvgs.ts                       All 10 logos (inline SVG)

When editing JSON, watch your commas , and brackets { } carefully.
A single wrong comma will stop the page from opening.


--------------------------------------------------------------------------
  5.  ***  CHANGING DATES  --  5 FILES  ***
--------------------------------------------------------------------------

THIS IS VERY IMPORTANT. If a conference date changes, you must update it
in 5 files. If you miss even one, the SAME page will show TWO different
dates.

  1. data\<slug>\conference.json
        dateline, dates, dates_short, start_date_iso,
        abstract_deadline, early_bird_deadline

  2. data\<slug>\marketing.json
        key_dates  ->  Abstract Deadline, Early Bird Ends,
                       Acceptance, Conference Opens

  3. data\<slug>\registration.json
        phases[Early Bird].closes, phases[Late].closes,
        form.checkin_dates, form.checkout_dates

  4. data\<slug>\common.json
        FAQ entry "How can I register"            (early bird date)
        FAQ entry "abstract submission deadline"

  5. data\<slug>\seo.json
        pages.index.description       (conference dates)
        pages.abstract.description    (deadline)

After changing them, scroll through the whole page in the browser and
confirm the date is the same everywhere.

--------------------------------------------------------------------------
  7.  BUILD   (Check that your change is correct)
--------------------------------------------------------------------------

ALWAYS run the build before you push:

    npm run build

If it says "Compiled successfully", you are fine.
If you get an error -- DO NOT PUSH. Fix the error first.

IMPORTANT:  npm run dev  does NOT catch these errors.
            Only  npm run build  catches them.
            That is why you must run the build before pushing.


--------------------------------------------------------------------------
  8.  PUSHING YOUR CHANGES TO GITHUB
--------------------------------------------------------------------------

    git status                    (see what you changed)
    git add .
    git commit -m "Update cardiology dates and venue"
    git push origin main

The first time you push, GitHub will ask you to log in.
You need your GitHub username + a Personal Access Token (NOT your password).

How to create the token:
    github.com  -->  Settings  -->  Developer settings
    -->  Personal access tokens  -->  Tokens (classic)
    -->  Generate new token  -->  tick the "repo" scope  -->  Generate
    Copy the token and paste it where the password is asked.
    (The token is shown only once -- save it somewhere safe.)

CAREFUL: git push sends your work to the main branch. Along with your
         change, any other pending commits will also go live.
         So before pushing, run:

             git log HEAD..origin/main

         If anything shows up in the result, tell the team.

--------------------------------------------------------------------------
  12.  TROUBLESHOOTING
--------------------------------------------------------------------------

  Page will not open / 500 error
      -->  There is a wrong comma or bracket in the JSON file you edited.
           Paste that file into  https://jsonlint.com  to check it.

  "npm is not recognized"
      -->  Node.js is not installed. Install it from nodejs.org, then
           close Command Prompt and open it again.

  npm run dev  --  port already in use
      -->  Another dev server is already running. Close the other
           terminal, or use   npm run dev -- -p 3001

  git pull  gives a conflict
      -->  Your changes clash with someone else's changes.
           Do not try to fix it yourself -- tell the team.

  I changed the date but the page still shows the old one
      -->  You missed one of the 5 files. Check Section 5 again.

  Build fails with "Type error"
      -->  This is a TypeScript problem. Take a screenshot and send it
           to the team.
